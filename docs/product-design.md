# 产品设计 — ExEditor（有经验的编辑）

## 定位

ExEditor 是 Obsidian 里一位**有经验的编辑**：你写作时随叫随到，圈出问题、解释原因、给出改法；你下指令时，它能整段重写。它对文稿安全负有绝对责任——**绝不弄丢你的稿子**。

前身是「编辑建议（editing-suggestions）」插件，因整体不可用而重建：安全核心保留，交互与架构重做。

## 用户与场景

- 主要用户：在 Obsidian 中进行中文长文写作的作者（个人项目，首要用户即作者本人）。
- 典型场景：写完一段想快速过一遍语病；写完全文要一次系统性校对；对某段不满意，让 AI 按自己的要求重写；改坏了要能一键撤销/恢复快照。
- 核心判断「有用」的标准：检查一次就能放心接受建议，全程没有一次错替换、丢字或卡死。

## 核心流程

```
写作 → 触发检查（段落/选中/全文）→ AI 返回建议（原文+改法+解释）
     → 浏览（侧边栏列表 / 编辑器波浪线+悬浮卡片）
     → 决策（接受 = 单事务替换、可撤销 / 忽略）
     → 需要时：快照恢复、按指令重写
```

## 能力清单（按里程碑交付，详见 roadmap.md）

1. **圈问题**：语法、错别字、表达问题，分类分级展示，字符级 diff 对比原文与改法。
2. **解释与改法**：每条建议带简短理由，一键应用。
3. **按指令改**：自定义指令双模式——建议式（结果进入建议流）与重写式（整段重写，预览确认后应用）。
4. **稿子保险**：唯一定位协议、保护区域、单事务应用、应用前快照、备份恢复。
5. **随叫随到**：段落/选中/全文三种范围，进度可见、可随时取消；远期支持闲置段落自动检查。

## 安全协议（继承自旧版并保持，M1 起为硬约束）

- **模型只报「原文片段 + 替换文本」**，不信任任何坐标；插件在文中自行定位。
- **唯一出现定位**：原文片段在非保护区域必须唯一出现，否则该建议标 stale 丢弃。
- **保护区域**（frontmatter、代码块、数学、wikilink、图片、行内代码、callout 标记）内的定位结果一律无效。
- **单事务应用**：批量接受合并为一次编辑器事务，Ctrl+Z 一次完整撤销；应用前自动快照。
- 实现位置：纯函数模块 `validate` / `protected` / `apply` / `diff` / `parse`（M1 从 legacy 移植 + 全部单测）。

## UI 架构原则（与旧版的分水岭）

1. **精确更新**：界面按条目 id 增删改 DOM，禁止整体重建；焦点、光标、滚动位置天然保留，不做任何保存/恢复 hack。
2. **控制器分层**：`Plugin` 类只负责生命周期与注册；检查编排、建议管理、快照备份各自独立成控制器，UI 只消费状态。
3. **可取消优先**：所有 AI 请求经 AbortController 可中断；长时间任务必须展示进度并提供取消。
4. **安静克制**：无建议时不打扰；有建议时不跳动；token 用量等噪音信息不上界面。

## 非目标

- 不做移动端深度适配（`isDesktopOnly: false` 仅为不排斥，不承诺）。
- 不做语法解析器级（LSP/本地规则引擎）检查，检查能力完全来自 LLM。
- 不做云端服务、账号体系、多人协作。
- 不做通用 AI 聊天侧边栏（专注校对与改稿）。
